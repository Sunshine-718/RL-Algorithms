01. 为什么需要 Dreamer V2？

像素空间庞大，逐帧用真实环境训练策略成本很高。Dreamer V2 把感知、预测与行为学习分开，让大部分策略更新发生在紧凑潜状态中。

表示

编码器和后验把图像压缩为确定状态 hₜ 与多个类别变量 zₜ。

预测

RSSM 先验仅凭历史状态与动作预测未来潜状态，并由多个预测头约束其信息量。

行为

Actor-Critic 从后验状态出发，在 RSSM 先验生成的轨迹中反复学习。

直通 categorical 采样

前向计算使用真正的 one-hot 样本，反向计算把梯度交给 softmax 概率。这让离散状态既有明确类别，又能端到端训练。

z = one_hot(sample(logits))
z_st = z + softmax(logits) − stop_grad(softmax(logits))

KL balance 与 free nats

后验正则项更新 q，先验拟合项更新 p。本实现给先验 0.8 权重，并在平均 KL 低于 1 nat 时停止继续压缩。

L_KL = 0.2 KL(q || sg(p)) + 0.8 KL(sg(q) || p)

离散动作：Categorical + REINFORCE

  • 环境动作返回 int，世界模型接收 one-hot。
  • 采样动作不可导，Actor 用 log_prob × advantage 更新。
  • 熵系数默认 1e-3。

连续动作：tanh-Normal + dynamics gradient

  • 重参数采样后经 tanh 限制到 [-1, 1]。
  • 回报梯度穿过冻结的世界模型回到 Actor。
  • 熵系数默认 1e-4。

05. 一次训练更新发生了什么

DreamerV2Agent.step() 先更新世界模型，再把后验状态展平为想象起点，更新 Actor 和 Critic。

  1. 1采样连续序列

    observation [B,T,C,H,W]，首帧动作与奖励清零。

  2. 2更新世界模型

    编码整段观测，逐时刻执行 obs_step，联合计算四类损失。

  3. 3从后验状态出发

    把 [B,T,…] 展平；排除真正终止状态。

  4. 4生成想象轨迹

    Actor 与 RSSM 先验滚动 H=15 步。

  5. 5更新 Actor

    离散动作使用 REINFORCE；连续动作使用 dynamics gradient。

  6. 6更新 Critic

    拟合停止梯度的 λ-return；每 100 次更新同步目标 Critic。

06. 运行、评估与排错

训练入口保持仓库现有脚本风格：在文件底部修改 update 和 continuous，再直接运行。

运行命令

训练：设置 update = 1；评估：设置 update = 0。连续与离散模式由 continuous 控制。

python Dreamer/dreamerv2.py
python -m unittest discover -s tests -p 'test_dreamerv2.py' -v
观测形状是否正确？

教学实现只接受 CarRacing 包装器输出的 uint8 [2,96,96] CHW 图像。固定输入让四层卷积严格得到 6×6 特征，四层转置卷积严格恢复为 96×96。回放采样后形状为 [B,T,2,96,96]，并归一化到 [-0.5,0.5]。

动作编码是否正确？

离散环境动作是整数，进入 RSSM 前转换为 one-hot；连续动作是长度为 action_dim 的 float32 向量，并要求环境动作范围已经缩放到 [-1,1]。

terminated 与 truncated 如何处理？

两者都会结束 episode，避免序列跨回合。只有 terminated 把继续目标设为 0；时间限制 truncated 保留 bootstrap。

为什么 loss 出现 NaN 或 Inf？

先检查原始观测和动作是否有限，再查看模型、Actor、Critic 的梯度范数。实现会进行梯度裁剪，但无法修复输入中的非有限数。

如何判断世界模型是否学到了有效状态？

数值损失只说明优化过程。还应比较 reconstruction 与真实序列，并检查仅依赖先验滚动时的图像、奖励和继续预测是否随时间保持合理。

检查点包含哪些内容？

保存世界模型、Actor、Critic、目标 Critic、三个优化器和更新次数。文件名根据连续或离散模式分别生成，避免互相覆盖。
